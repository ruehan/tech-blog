## 마우스는 그대로인데 동작은 다시 시작된다 {#symptom}

모니터 위에서 포인터를 조금 움직이면 테두리 효과가 처음부터 다시 나타났다. 화면에서는 하나의 모니터지만, 3D 모델 안에는 화면과 프레임처럼 여러 메시가 있다. 한 메시를 떠나는 이벤트를 모니터 전체를 떠난 것으로 해석하고 있었다.

## 메시보다 상호작용 단위로 판단하기 {#interaction-root}

포인터가 닿은 메시에서 부모를 따라 올라가 상호작용 식별자를 찾는다. 같은 식별자 안의 이동은 동일한 호버 상태로 유지한다. 하위 메시 사이에서 잠깐 발생하는 이탈은 100밀리초 동안 기다렸다가 확정한다.

```typescript
function interaction(object: Object3D | null): string | null {
  while (object) {
    if (object.userData.interaction_id) {
      return object.userData.interaction_id;
    }
    object = object.parent;
  }
  return null;
}
```

HTML 안내 버튼과 캔버스 사이를 오갈 때도 같은 기준을 적용한다. 버튼 위에서는 버튼이 포인터를 소유하고, 이미 지나간 메시 정보로 호버가 되돌아가지 않도록 처리했다.

## 자세와 발광을 함께 연결하기 {#blend}

이벤트만 안정화해도 애니메이션 교체 시점의 끊김은 남았다. 이전 동작을 즉시 정지하면 모델이 기본 자세로 돌아가기 때문이다. 진입·유지·복귀 사이를 0.16초 동안 혼합하고, 별도 데이터로 재생하는 발광 효과에도 같은 전환을 적용했다.

- 같은 오브젝트 안에서 메시를 바꾸어도 진입을 반복하지 않는다.
- 짧게 이탈했다 돌아오면 유지 상태가 이어진다.
- 진입 도중 실제로 떠나거나 다시 들어와도 자세가 갑자기 바뀌지 않는다.

## 프레임으로 확인하기 {#verification}

브라우저에서 포인터를 실제로 움직이고 매 프레임의 크기와 위치를 기록했다. 네 오브젝트의 유지 상태, 빠른 재진입, 동작 중 방향 전환을 검사했다. 최종 화면뿐 아니라 그 화면에 도착하는 과정도 확인해야 했다.
