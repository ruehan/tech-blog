## 공간을 입구로 삼기 {#a-room-as-an-entry}

이 블로그는 작은 방에서 시작했다. 책장에는 글을, 컴퓨터에는 프로젝트를 연결하고 싶었다. 베이스와 심레이싱 장비도 같은 공간에 두었다. 내가 만드는 것과 좋아하는 것이 한눈에 보이는 입구를 생각했다.

첫 화면은 React Three Fiber로 구현했다. 방 안의 책을 누르면 책이 펼쳐지고, 모니터를 누르면 컴퓨터 안으로 들어간다. 심레이싱 장비에서는 서킷의 운전석으로 이어진다. 메뉴를 고르는 동작에 공간의 맥락을 더한 셈이다.

![책장과 컴퓨터, 베이스와 심레이싱 장비가 놓인 3D 방 화면](/images/posts/room-blog/room.png "실제 웹 화면. 방 안의 오브젝트와 왼쪽 메뉴로 글과 프로젝트에 접근한다.")

직접 만들어보니 가장 많이 손본 부분은 오브젝트 자체보다 **화면 사이의 전환**이었다. 방에서 책으로, 펼쳐진 책에서 본문으로, 다시 방으로 돌아올 때 시선이 자연스럽게 이어져야 했다.

## 장면과 콘텐츠의 역할 {#scene-and-content}

React는 글과 메뉴를, React Three Fiber는 3D 장면을 담당한다. 방·컴퓨터·서킷을 각각의 GLB 파일로 나누고, 선택한 공간에 필요한 모델을 불러온다.

| 공간 | 연결한 경험 |
| --- | --- |
| 방 | 책에서 글 읽기, 베이스 연출, 조명 전환 |
| 컴퓨터 | 폴더를 열어 프로젝트 탐색 |
| 서킷 | 출발선의 운전석과 차량 외부 시점 |

책을 누르면 원본 애니메이션을 처음부터 끝까지 재생하는 대신, **책이 펼쳐진 지점에서 멈추고 글 화면을 연다.** 큰 책 화면의 왼쪽에는 목록을, 오른쪽에는 본문을 배치했다. 창을 닫으면 책을 덮는 구간부터 이어 재생한다.

이때 방을 지우고 다시 만드는 대신 글을 읽는 동안 렌더링을 쉬게 했다. 책을 닫았을 때 기존 카메라와 조명 상태로 돌아갈 수 있도록 하기 위해서다.

하지만 모든 방문자가 3D 공간을 둘러보고 싶어 하지는 않을 것이다. 그래서 글을 바로 찾고 읽을 수 있는 `/journal` 화면도 만들었다.

![검색과 태그, 글 목록 옆에 시계와 달력이 배치된 일반 블로그 화면](/images/posts/room-blog/journal.png "일반 블로그에서는 모델을 불러오지 않고 바로 글을 읽는다. 색감과 작은 메뉴 버튼은 방 화면에서 이어받았다.")

일반 블로그에 직접 들어오면 3D 모듈과 모델을 요청하지 않는다. 방에서 일반 블로그로 전환할 때도 캔버스를 해제한다. 두 화면은 같은 글 데이터를 사용하므로, 글을 어느 쪽에 따로 올릴지 고민할 필요는 없다.

## 작은 전환이 만드는 차이 {#small-transitions}

처음에는 기본 방 화면과 클릭 애니메이션의 첫 프레임이 맞지 않았다. 메인 화면을 조금 더 크게 보여주려고 적용한 확대 배율이 애니메이션 카메라에도 영향을 주었다. 클릭하는 순간 화면이 재정렬되는 것이 눈에 띄었다.

먼저 원본 애니메이션 카메라의 배율과 기본 방의 추가 확대를 분리했다. 이후 클릭 직전의 카메라 위치·회전·배율과 오브젝트 자세를 저장하고, 원본 첫 프레임까지 0.65초 동안 보간한 뒤 연출을 시작하도록 바꾸었다.

카메라 회전처럼 방향을 다루는 값에는 쿼터니언 보간을 사용한다. 아래는 전환에서 사용하는 계산의 핵심이다.

```typescript
camera.position.lerpVectors(from.position, to.position, progress);
camera.quaternion.slerpQuaternions(from.quaternion, to.quaternion, progress);
camera.zoom = from.zoom + (to.zoom - from.zoom) * progress;
camera.updateProjectionMatrix();
```

실제 구현에서는 시야각과 오브젝트의 위치·크기, 조명과 재질 변화도 함께 연결한다. 방으로 돌아오는 마지막 구간에도 같은 방식의 전환을 넣었다.

> 시작 화면과 끝 화면만 확인해서는 중간의 끊김을 놓치기 쉽다. 사용자가 보고 있던 상태에서 다음 상태로 이동하는 과정까지 확인하는 것이 이번 작업의 기준이었다.

검증할 때는 실제 브라우저에서 카메라를 회전한 뒤 책이나 장비를 클릭했다. 연출 중 일시정지·건너뛰기·취소, 글을 닫은 뒤 복귀, 모바일에서의 화면 전환도 확인했다.

## 다음에 쌓아갈 것 {#next}

지금은 글을 Markdown 파일로 관리한다. 파일에 제목·날짜·태그와 본문을 작성하면 책 화면과 일반 블로그의 목록·검색·목차에 함께 반영된다. 초안은 개발 중에 미리 보고, 배포용 빌드에서는 제외한다.

다음으로는 이 공간에서 만든 것과 배운 것을 꾸준히 기록하려 한다. 본문은 충분히 읽기 편한지, 모바일에서 글을 찾기 쉬운지 실제 글을 쌓으며 다듬을 생각이다.

현재 서킷은 운전석에서 둘러보는 공간이며 차량 주행이나 물리 시뮬레이션은 포함하지 않는다. 검색 엔진과 공유 미리보기를 위한 정적 본문 생성, 모델 용량과 모바일 성능 개선도 후속 작업으로 남아 있다.
