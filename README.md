# Hangyu’s room

React 19 + React Three Fiber 9 + Drei + TypeScript + Vite로 만든 3D 공간 탐색 웹입니다.

## 실행

```sh
npm install
npm run dev
```

터미널에 표시된 로컬 주소를 엽니다. `npm run build`는 타입 검사와 프로덕션 빌드, `npm run preview`는 빌드 미리보기, `npm test`는 에셋·애니메이션과 Markdown 메타데이터·렌더링·초안 제외 검증을 실행합니다.

`npm run test:browser`는 설치된 Chrome으로 월드 전환·조명·모바일·로딩 실패 복구를 검증합니다. 다른 환경에서는 `npx playwright install chromium` 후 `PLAYWRIGHT_CHANNEL=chromium npm run test:browser`를 사용합니다.

`npm run test:static`는 프로덕션 빌드 후 정적 HTML·공유 태그·초안 제외와 JavaScript 없이 읽기 및 클라이언트 전환을 검증합니다.

## 구현 범위

- 메인 방: 오프닝, 책·베이스 클릭 연출, 개별 호버, 모니터·시뮬레이터 포털 접근, 조명 전환.
- 컴퓨터: 데스크톱 애니메이션, Projects 폴더 열기·닫기.
- 서킷: 운전석 1인칭 시점으로 진입하며, 서킷 전체·차량 근접 시점으로 전환 가능. 시점 초기화는 운전석으로 복귀.
- 공통: 왼쪽의 작은 아이콘 메뉴에 방·글·프로젝트·컴퓨터·서킷 바로가기, 공간별 조작, 화면 설정을 모았습니다. 글·프로젝트는 바로 열고, 3D 오브젝트는 기존 클릭 연출을 재생합니다. 일시정지, 시점 초기화, 로딩·오류 상태, 모바일·가로 화면을 지원합니다. 운전석 외 시점에서는 드래그 회전과 확대 지원.
- 동작 줄이기 설정을 사용하면 애니메이션을 기본 일시정지합니다. Esc는 연출 취소 또는 방으로 복귀합니다.
- 블로그: 원본 Book_Click 클립의 접근·펼치기까지만 재생한 후 5초 지점에서 큰 책 형태의 읽기 화면을 엽니다. 읽는 동안 3D 렌더링을 멈추며, 포스트 창을 닫으면 같은 자세의 323/24초(약 13.46초) 지점부터 곧바로 책을 덮고 방으로 복귀합니다. 중간 페이지 확대·축소 구간은 생략합니다. 왼쪽에는 태그 필터와 글 목록, 오른쪽에는 선택한 글을 함께 표시합니다. 글을 바꾸면 오른쪽 페이지만 책등을 축으로 살짝 넘어가며, 이전 글은 반대 방향으로 전환합니다. 목차, 관련 글, 링크 복사와 글별 스크롤 복원을 지원합니다. 모바일은 목록과 본문을 전환하고, 동작 줄이기 설정에서는 페이지 전환 애니메이션을 생략합니다.
- 프로젝트: 컴퓨터의 DesktopFolderOpen 클립이 끝나면 목록을 표시합니다. 열리는 도중 닫으면 목록을 열지 않습니다. 프로젝트 상세 페이지에는 현재 블로그 프로젝트 1개를 등록했습니다.
- 책·베이스·모니터·심레이싱의 클릭 연출은 현재 카메라 위치·회전·배율과 호버 자세에서 원본 첫 프레임까지 0.65초 동안 부드럽게 정렬한 뒤 시작합니다. 방으로 복귀하는 책·음악 연출과 최초 진입 연출도 마지막 프레임에서 기본 방의 카메라·자세·조명으로 0.65초 동안 전환한 뒤 조작을 다시 활성화합니다. 전환 중에도 일시정지·건너뛰기·Esc 취소가 가능합니다.
- 책의 진입 연출은 건너뛰어 바로 읽거나 Esc로 취소할 수 있습니다. 동작 줄이기 또는 일시정지 상태에서도 콘텐츠에 바로 접근할 수 있습니다.

## 글과 프로젝트

- `/journal`: 3D 없이 읽는 일반 블로그. 방 메뉴 맨 위의 `2D` 버튼으로 전환합니다. 기존 녹색 아이콘 메뉴와 종이 질감, 작은 책등 모양을 유지하고 소개·장식 문구 없이 글 목록부터 보여줍니다. 모바일에서는 작은 메뉴를 하단에 배치합니다.
- 글 목록의 여백에 실제 현지 시간을 보여주는 탁상시계와 오늘을 표시하는 월간 달력을 배치합니다. 1,280px 이상에서는 본문과 메뉴를 제외한 양쪽 여백 전체에서 실제 소품 크기를 측정해 임의 좌표를 고릅니다. 소품 사이의 겹침을 피하고, 같은 방문의 난수 시드를 유지해 시계 갱신·글 왕복 때 같은 배치를 재현합니다. 화면 크기나 소품 높이가 바뀌면 다시 계산하며, 좁은 화면에서는 글 목록 아래에 모읍니다.
- 책상 소품의 스타트 라이트는 버튼을 눌러 시작하는 반응속도 게임입니다. 다섯 출발등이 차례로 켜지고 임의의 대기 시간 뒤 모두 꺼지면 클릭·터치·Space·Enter로 반응합니다. 조기 입력은 기록하지 않으며 최고 기록은 해당 브라우저에 저장합니다. 키를 누르고 있어도 반복 입력하지 않고, 탭 숨김·창/버튼 포커스 이탈·Esc·페이지 이동 시 진행 중인 라운드를 취소합니다. 10초 안에 반응하지 않으면 다시 시작할 수 있습니다. 소리와 자동 시작은 없습니다.
- 일반 블로그 메뉴의 달·해 버튼으로 밤에 읽기 테마를 전환합니다. 짙은 녹색 배경과 따뜻한 글자색을 본문·프로젝트·시계·달력에 적용하고, 선택은 브라우저에 저장합니다. 저장소를 사용할 수 없어도 현재 화면의 전환은 동작합니다.
- 일반 블로그 메뉴의 읽기 설정에서 글자 크기(작게·기본·크게)와 본문 너비(좁게·기본·넓게)를 고릅니다. 글과 프로젝트 본문에 즉시 반영하고 코드·표도 함께 조절하며, 선택은 브라우저에 저장합니다. 모바일에서는 화면 너비 안으로 제한하고, 기본값으로 되돌릴 수 있습니다.
- 일반 블로그의 본문 이미지와 프로젝트 상세 이미지를 누르면 확대 화면을 엽니다. 화면 맞춤과 원본 크기 보기를 전환하며 원본이 화면보다 크면 스크롤해 살펴봅니다. 닫기 버튼·배경 클릭·Esc로 닫으면 읽던 위치와 이미지 버튼의 키보드 포커스를 복원합니다. 링크가 걸린 이미지는 원래 링크로 이동합니다.
- 글 목차는 1200px 이상에서 오른쪽에 고정되고 현재 읽는 소제목을 표시합니다. 좁은 화면에서는 접을 수 있는 상단 목차로 바뀌며, 소제목을 선택하면 접힌 뒤 본문으로 이동합니다. 소제목 주소로 직접 진입하거나 브라우저 뒤로가기로 돌아와도 위치가 이어집니다.
- `/journal/posts/building-a-room-on-the-web`: 일반 블로그 글 본문. 목차·태그·관련 글·공유 링크도 일반 화면을 유지합니다.
- `/journal/projects`, `/journal/projects/hangyu-room`: 일반 블로그의 프로젝트 목록과 상세. 목록은 대표 프로젝트의 큰 실제 화면을 보여주고 `3D 방` / `2D 블로그` 버튼으로 미리보기를 전환합니다. 최근 작업과 관련 제작기를 함께 제공하며, 미리보기만으로는 3D 모델을 불러오지 않습니다.
- 일반 블로그의 검색은 제목·설명·태그·본문(소제목·목록·코드 포함)을 대상으로 하며 태그 필터와 함께 사용할 수 있습니다. 여러 검색어는 모두 포함된 글을 찾으며 대소문자와 연속 공백을 구분하지 않습니다. 검색어 지우기는 선택한 태그를 유지합니다. 본문 아래의 이전·다음 글은 현재 검색 결과 안에서 이동하고, 글 목록으로 돌아가면 검색 조건과 스크롤 위치를 복원합니다. `?tag=React&q=호버`처럼 검색 조건을 주소에 저장하고 목록으로 돌아갈 때 유지합니다. 직접 진입하면 3D 모듈과 GLB를 요청하지 않으며, 방에서 전환할 때는 캔버스를 해제합니다. 메뉴의 집 아이콘(`3D 방으로`)을 누르면 메인 방을 다시 불러옵니다.
- 검색 결과에는 일치한 본문·코드 주변 문장을 표시하고 검색어를 강조합니다. 제목과 태그도 함께 강조하며, 본문에 일치하는 부분이 있으면 결과 클릭 시 해당 블록으로 이동합니다. 검색 주소를 새로고침해도 같은 위치로 이동하고, 목록으로 돌아갈 때 검색 조건은 유지합니다. 본문에 없고 메타데이터에만 일치하면 기존 소개를 보여줍니다.
- 시리즈에 속한 글은 본문 앞에 접을 수 있는 시리즈 목록과 현재 순서를 표시합니다. 목록 안의 이전·다음 편은 시리즈 순서대로 이동하며, 2D/책 읽기 모드를 유지합니다. 기존 제작기 3편은 `이 블로그를 만드는 과정`으로 묶었고, 초안 2편은 개발 화면에서만 표시합니다.
- `/posts`: 글 목록. `?tag=React`처럼 태그를 주소에 저장합니다.
- `/posts/building-a-room-on-the-web`: 글 본문. 주소로 직접 들어오면 3D 장면을 불러오지 않습니다.
- `/projects`: 프로젝트 목록.
- `/projects/hangyu-room`: 이 블로그의 프로젝트 소개와 관련 작업 기록.

`content/posts/*.md`가 두 화면에서 공유하는 글 원본입니다. 첫 제작기는 실제 스크린샷과 현재 구현 내용을 담은 공개 글이며, 나머지 두 글은 초안입니다. `src/content.ts`는 정렬된 글 데이터·태그·검색만 담당하고 `src/Blog.tsx`와 `src/Journal.tsx`가 이를 함께 사용합니다.

### 글 작성

일반 블로그 사이드의 `요즘 하고 있는 것`은 `content/now.json`에서 관리합니다. `items`의 `label`·`title`·`description`·`href`와 실제 내용을 수정한 날짜인 `updated` (`YYYY-MM-DD`)를 함께 갱신하세요. 링크는 공개된 글이나 프로젝트 주소를 사용하고, 항목은 2~3개로 짧게 유지합니다.

```sh
npm run post -- my-new-post "새 글 제목"
```

`content/posts/my-new-post.md` 초안을 만들고 기존 파일은 덮어쓰지 않습니다. 또는 `content/post-template.md`를 `content/posts/` 아래에 복사해도 됩니다.

```yaml
---
title: "새 글 제목"
description: "목록에 표시할 짧은 설명"
date: 2026-10-21
tags: [React, 인터랙션]
draft: true
---
```

- 파일명(확장자 제외)이 글 주소가 됩니다. 영문 소문자·숫자·하이픈을 사용합니다. 파일명을 바꾸어도 주소를 유지하려면 `slug: my-new-post`를 지정합니다.
- `title`, `description`, `date`는 필수입니다. `tags`는 선택이며 기본값은 빈 목록입니다. `minutes`를 지정하지 않으면 본문 길이로 읽기 시간을 계산합니다.
- `draft: true` 또는 draft 생략: `npm run dev`에서만 보입니다. `draft: false`: 배포용 빌드에도 포함됩니다. 초안은 배포용 목록·검색·직접 글 주소뿐 아니라 생성된 콘텐츠 데이터에서도 제외합니다. 공개용 이미지 파일은 `public`에 두므로 초안 이미지까지 비공개가 되는 것은 아닙니다.
- 날짜 내림차순으로 정렬하며 같은 날짜는 파일명 순서를 따릅니다. 중복 주소, 잘못된 날짜·필드, 빈 본문은 파일명을 포함한 오류로 알립니다.
- 선택 필드 `series: { slug: building-hangyu-room, title: "이 블로그를 만드는 과정", order: 1 }`로 시리즈를 지정합니다. 같은 slug의 제목은 같아야 하며 order는 중복 없는 양의 정수입니다. 초안도 메타데이터 일관성은 검사하지만 공개 시리즈 목록에는 포함하지 않습니다.
- 선택 필드 `image: /images/posts/글주소/cover.png`로 공유용 대표 이미지를 지정할 수 있습니다. 생략하면 본문의 첫 이미지, 이미지가 없으면 방 스크린샷을 사용합니다. 로컬 대표 이미지도 빌드할 때 존재 여부와 이미지 형식을 검증합니다.
- 개발 서버에서는 파일 추가·수정·삭제 시 화면을 새로고침합니다. 배포된 사이트에 반영하려면 다시 빌드해야 합니다.

본문은 `## 소제목`부터 작성합니다. `##`는 목차에 자동 반영되고 중복 제목에는 번호가 붙습니다. 기존 링크를 유지하려면 `## 소제목 {#stable-id}`처럼 ID를 지정할 수 있습니다. 굵게·기울임·인라인 코드·링크·중첩 목록·인용문·표·체크리스트를 지원합니다.

코드는 언어를 지정한 fenced code block으로 작성합니다. 빌드 시 구문을 강조하고 두 읽기 화면에서 원문 복사를 지원합니다. 지원하지 않는 언어는 일반 코드로 표시합니다. 클립보드 접근이 막히면 직접 선택할 수 있는 코드 입력란을 제공합니다.

이미지는 `public/images/posts/글주소/`에 저장한 뒤 다음과 같이 연결합니다.

```markdown
![화면을 설명하는 대체 텍스트](/images/posts/my-new-post/screen.png "이미지 아래 캡션")
```

이미지 주소는 `/`로 시작하는 공개 파일 경로 또는 `https://` 주소를 사용합니다. 로컬 이미지의 존재와 크기를 빌드 시 확인해 로딩 전부터 공간을 확보합니다. 외부 이미지는 네트워크 상태에 영향을 받으므로 가능한 한 로컬 이미지를 사용합니다. 스크린샷 원본은 `public/images/posts/room-blog/`에 있습니다.

`vite.config.mjs`와 `scripts/content.mjs`가 Markdown을 빌드 시 변환합니다. 브라우저에 Markdown 파서나 구문 강조 라이브러리를 보내지 않으며, 정제된 노드를 React로 렌더링합니다. 원시 HTML은 실행하지 않고 문자로 표시합니다. 초안 작성·공개는 파일 수정과 빌드 단계에서 이루어지며 외부 게시나 배포를 자동 실행하지 않습니다.

### 정적 페이지와 공유 정보

`npm run build`는 클라이언트 번들을 만든 뒤 `scripts/prerender.mjs`로 공개 글·목록·프로젝트의 HTML을 `dist/경로/index.html`에 생성합니다. 같은 React 본문 컴포넌트를 서버에서 렌더링하므로 JavaScript 없이도 글·코드·표·이미지·시리즈를 읽고 링크를 따라갈 수 있습니다. 브라우저에서는 초기 HTML을 React 화면으로 교체하고 검색·읽기 설정·이미지 확대를 연결합니다. 초안 본문과 주소는 정적 페이지 및 프로덕션 콘텐츠 모듈에 포함하지 않습니다.

대표 도메인은 `site.config.mjs`의 **https://hangyu.blog**입니다. 다른 도메인으로 빌드하려면 `SITE_URL=https://다른도메인 npm run build`로 지정합니다. 공개 글마다 제목·설명·Open Graph·Twitter 카드·BlogPosting 구조화 데이터를 HTML에 넣고, SPA 내 이동 시에도 정보를 갱신합니다. 대표 주소는 `/journal/posts/글주소`이며 `/posts/글주소`에도 같은 대표 주소를 지정합니다. 쿼리와 해시는 대표 주소에 포함하지 않습니다. `dist/sitemap.xml`에는 대표 공개 주소만, `dist/robots.txt`에는 사이트맵 위치를 기록합니다.

호스팅은 생성된 파일과 디렉터리의 `index.html`을 우선 제공해야 합니다. 없는 주소에는 `dist/404.html`을 **404 상태**로 제공하고, 모든 주소를 루트 `index.html`에 200으로 연결하는 무조건 SPA 재작성은 피합니다. 그래야 공유 로봇이 글별 HTML을 받고 없는 글도 올바르게 처리됩니다. 개발 서버의 임시 HTML은 정적 배포 결과와 다르므로 공유 정보 검증에는 빌드 결과를 사용합니다. 이 작업은 배포나 검색엔진 제출을 자동 실행하지 않습니다.

구현 기준: [Google JavaScript SEO](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics), [Open Graph](https://ogp.me/), [사이트맵 문서](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap).

## 에셋과 구조

`blog-room-v27/`이 원본입니다. `scripts/prepare-assets.mjs`가 실행·빌드 전에 필요한 GLB를 최적화해 `public/assets/`로 생성하고 JSON과 미리보기 이미지를 복사합니다. Blender 파일과 검증 자료, 선택용 아틀리에, 정적 베이크 비교본은 웹 번들에 포함하지 않습니다. 컴퓨터와 서킷은 해당 월드에 진입할 때 불러옵니다.

- 모델은 Meshopt 압축과 중복 데이터·불필요한 키프레임 제거를 적용합니다. 정점 정밀도를 줄이는 양자화, 메시 단순화, 텍스처 손실 압축은 하지 않습니다. 원본 노드·상호작용 정보와 sidecar가 참조하는 재질 인덱스를 유지합니다. 디코더는 기존 Drei 로더에 포함되어 외부 CDN 요청이 필요 없습니다.
- 실행용 모델 4개의 합계는 약 38.8MB에서 19.2MB로 줄었습니다. 원본·처리 스크립트·의존성이 같으면 생성 결과를 재사용하며, `public/assets/`를 지운 뒤 `npm run assets`로 다시 생성할 수 있습니다. 원본 파일은 수정하지 않습니다.
- 애니메이션의 재질·조명 연결은 로딩 시 계산하고 샘플 버퍼를 재사용합니다. 애니메이션 대상이 아닌 노드는 로컬 변환 행렬의 반복 계산을 생략합니다.
- 방과 데스크톱의 기존 Idle 애니메이션은 계속 재생합니다. 일시정지 상태와 정적인 서킷은 조작·화면 변경 시에만 그리며, 숨겨진 탭과 글 읽기 중에는 렌더링을 멈춥니다. 탭 복귀 시 연출을 건너뛰지 않고 이어갑니다.
- 왼쪽 화면 설정의 **일반 / 최적화** 스위치로 같은 장면의 렌더링 품질을 즉시 전환합니다. 기본값은 최적화이며 선택은 로컬에 저장합니다. 일반은 기존 DPR 1–1.5, 2048 그림자와 기본 투과 효과 해상도를 사용합니다. 두 모드 모두 같은 무손실 압축 모델과 애니메이션을 사용합니다.
- 최적화 모드는 60fps를 목표로 지속적인 프레임 지연을 감지해 DPR을 약 0.6–1.5 사이에서 조절합니다. 초기 픽셀 예산은 150만이며, DPR이 1 미만이면 그림자는 1024, 투과 효과 해상도는 절반으로 낮춥니다. 회복은 천천히 시도하고 실패한 품질 단계는 반복하지 않습니다. HTML 글자·버튼과 카메라 구도·애니메이션 길이는 유지합니다. 고정 60fps 제한이나 모든 기기에서의 60fps 보장은 아닙니다.
- `npm test`는 압축 전후 정점·모프·삼각형·노드·재질 연결과 키프레임 및 중간 시점의 애니메이션 자세를 비교합니다. `tests/browser/performance.spec.ts`는 렌더링 중단·재개와 회전 조작을 검증합니다.

`src/Room.tsx`는 GLB 클립과 24fps sidecar 데이터를 같은 시간으로 재생합니다. 오프닝의 첫 프레임을 표시 전에 적용하고, 마지막 프레임에서 기본 화면 배율로 부드럽게 연결합니다. 각 오브젝트의 Idle/Hover는 짧게 혼합해 전환하며, 하위 메시 사이의 포인터 이동으로 호버가 재시작되지 않도록 처리합니다. 클릭 연출 중에는 오브젝트 Idle과 카메라 조작을 멈춥니다. 조명은 별도 상태로 유지합니다. 원본 GLB 캐시를 변경하지 않도록 각 월드는 계층과 재질을 복제합니다.

`src/WorldScene.tsx`는 카메라, 조명과 월드 렌더링을, `src/App.tsx`는 내비게이션과 접근 가능한 UI를 담당합니다.

현재는 공간 탐색과 블로그 읽기 프로토타입입니다. 오디오, 차량 주행·물리, 서버·인증, 관리용 편집기는 포함하지 않습니다. PBR 조명은 웹에 맞춰 근사했으며 Blender 렌더와 픽셀 단위로 동일하지 않습니다. 이번 최적화는 전송량과 반복 계산을 줄이며, 움직이는 장면의 삼각형 수와 드로콜 수는 그대로입니다. 저사양 모바일 GPU를 위한 메시 단순화·배칭·텍스처 압축은 후속 작업입니다.
